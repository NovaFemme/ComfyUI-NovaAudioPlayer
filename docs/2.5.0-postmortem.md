# What went wrong with 2.5.0

**Pack:** `comfyui-novaaudioplayer` (Nova Audio Player / Nova Suite)
**Prepared:** 17 September 2026
**Basis:** the repository's own commit record. Every point below cites the commit that found or fixed it. Nothing here is inferred or reconstructed.

---

## 0. Two things to know before reading the list

**"2.5.0" is not named in any shipped document.** It does not appear in a single `.md`, `.toml` or `.py` file in the tree. The only way to identify the release is the `version` field in `pyproject.toml` across commit history: `2.3.4` at `840969c`, then `2.5.0` from the Nova Suite merge (`4f6e8f0`) through to `680643a`, then `2.6.0` in the current working tree. Everything below is therefore "what was found wrong in the 2.5.0 tree", not "what the 2.5.0 release notes admitted to" — there were none.

**2.5.0 never reached the registry.** As of today `api.comfy.org` lists the pack's versions as:

| Version | Status | Deprecated |
|---------|--------|------------|
| 2.3.4 | Active | No |
| 2.3.3 | Active | Yes |
| 2.3.2 | Active | Yes |
| 2.3.0 | Active | Yes |
| 2.2.1 | **Flagged** | Yes |
| 2.2.0 | **Flagged** | Yes |

Latest published is still **2.3.4**, and its public description is still the old three-node text. So the fault list below is the list of things that were caught in the 2.5.0 window — most of them *before* they could reach a user, one of them by the registry itself rejecting the publish.

One discrepancy worth flagging rather than papering over: commit `96725e5` refers to "the published 2.5.0 archive" and to "1.2 MB of the 1.88 MB published for 2.5.0". The registry shows no 2.5.0 version record today. Either an archive was uploaded and never became an active version, or that wording described the built archive rather than a live one. The commit record does not settle it.

## 1. What 2.5.0 was supposed to be

`bae82b1` — *Nova Suite: 26 nodes, a two-level menu, and a preset library.*

The pack went from **three nodes to twenty-six** (twenty-eight by the end of the window), arranged under seven menu groups driven by a new `nova_categories.py`, plus a 491-entry preset library. It was built and tested in the live ComfyUI install over nine days and committed from that install rather than re-typed.

That last sentence is the root cause of most of section 3. Code that only ever ran on one machine, where everything was already installed, carried assumptions that machine could not expose.

---

## 2. The publish blocker

**The registry rejected the publish outright: the description was too long.**
`5b928c7` — the 2.5.0 publish failed with *"description is too long"*. The submitted text was **1,423 characters**. The only length known to publish successfully is the **477** that went out with 2.3.4. The limit is undocumented and sits somewhere between the two, so the rewrite landed at **356** — short enough that the margin does not depend on guessing where the line is.

This is the single hard stop. Everything else in this document would have shipped.

## 3. Faults that would have broken installs

All three found by **reviewing** the merge, not by running it — the development machine has everything, so none of them could fail there. `2602c8d`.

**3.1 One missing optional package would have taken all 26 nodes off the menu.**
`utilities/nova_sql_dump.py` had `import pymysql` at module scope. `__init__.py` imports that module to register the node, so on any install without `pymysql` the `ImportError` propagates and the **entire pack disappears** — twenty-six nodes gone over one optional database feature. `pymysql` is not in ComfyUI's requirements and, at that point, was not declared in `pyproject.toml` either. Fixed to degrade the way `scipy` and `soundfile` already did: absent until used, then a message saying what to install. Verified by blocking the import and confirming the module still loads and still registers `NovaSQLDump`.

`7c54f61` then also declared `pymysql` as a dependency — and recorded why declaring is *not* the fix on its own: declaring covers the registry and ComfyUI-Manager install paths and does nothing for the very common path where somebody clones straight into `custom_nodes` and never runs pip. On that path a declared-but-absent package is still an `ImportError`. The same commit audited every third-party import in the shipped tree and confirmed `soundfile`, `mutagen`, `pymysql`, `torchcodec`, `acestep` and `demucs` are all lazy or guarded, and that nothing outside ComfyUI's own requirements is imported at module scope.

**3.2 The developer's home directory was published in seven widget defaults.**
Seven widget placeholders hardcoded `/home/novaf/...`. That leaks the username and the folder layout, and shows every other user a path that does not exist on their machine. Changed to `~/`. (`profiles/` was already kept out of the package for the same class of reason — the two saved NamePath profiles record a real database path, a real music library folder and an album name.)

**3.3 Eight modules used imports that only work inside ComfyUI.**
Eight modules imported `nova_categories` with a bare `from ..nova_categories`. That resolves when ComfyUI imports the pack as a package and nowhere else — the test suite, which loads modules by file path, got *"attempted relative import beyond top-level package"*. Fourteen other modules in the new code already guarded this; these eight did not. A real portability bug that happened to surface as a test failure.

## 4. Faults that would have made the pack invisible or mis-filed

**4.1 The registry could not read the node list — and would have listed zero of twenty-eight.**
`1c89381`. `__init__.py` built `NODE_CLASS_MAPPINGS` by `**`-spreading each module's own dict into one. Valid Python, and completely invisible to the registry's **static** parser: the file contained **zero literal node names and forty `**` spreads**. The registry page therefore showed no nodes. Confirmed by comparing four packs' `/comfy-nodes` endpoints — kjnodes and videohelpersuite populated, rgthree and Nova null. Fixed by spelling out the keys and importing the classes directly, with `dev/tests/test_registry_nodes.py` added so it cannot silently regress.

This is worth stressing: it is not a 2.5.0 regression, it is a **pre-existing defect that 2.5.0 would have carried forward at twenty-eight nodes instead of three.**

**4.2 A node created a menu category of its own.**
`9cc59f1`. Nova Lyric Score hardcoded `CATEGORY = "Nova Audio Player/Transcription"` — importing the `ANALYSIS` constant and never using it — which created a stray top-level category outside the pack's seven groups. It was also the one node missing from the hand-written menu map, which listed 27 of 28.

**4.3 `ALL_CATEGORIES` listed six of seven constants.**
`069c553`. `REPORT` was missing. Nothing iterated the list at the time, which is exactly why it would have been wrong the first time something did.

## 5. Metadata and documentation that was factually wrong

**5.1 The README described three nodes; the pack shipped twenty-eight.**
`96725e5`. Every version since 2.3.x published a README written for the player, Madow Inputs and Madow Unpack. The registry page would have said twenty-eight nodes and the README one click away said three — the first thing a visitor hits. Rewritten around the seven menu groups, a table per group, 37 images covering 14 of the 28 nodes.

**5.2 Three factual claims in that README were false**, all verified against the archive rather than the working tree:

- *"No dependencies beyond what ComfyUI already ships"* — false. `mutagen` and `pymysql` are declared and required.
- *"scipy … falls back to plain RMS"* — no longer described the code. The fallback keeps the channel power-summation rule and loses only K-weighting and gating, which is the whole substance of the LUFS fix. Mastering decisions are made against that number.
- Install instructions still led with `git clone`. The registry is the supported route.

**5.3 The `pyproject` description predated eight nodes and the entire Data Viewers group.**
`069c553`. Rewritten for twenty-eight, and it now also states the limits: separate ACE-Step install required, nothing downloaded or installed by the pack, verified on Linux/ROCm with Windows, macOS and CUDA untested.

**5.4 Help-page coverage was 9 of 28.**
`cb6ea0f` took it to **16 of 28** by writing pages for the seven mastering and viewer nodes — the things a widget label cannot tell you (that `Off` is a true PCM pass-through; that `NOT_REACHED` alone is not a failure; that Master Identity converts nothing and bit depth is publication *intent*; that PCM24 landing on `REPRODUCTION_MATCH` rather than `BIT_EXACT` is correct arithmetic, not a bug to hunt).

**5.5 The most complicated node in the training group had no help page at all.**
`069c553`. `web/docs/NovaACELoRATrainer/en.md` was missing while its three siblings had one. It now covers the `0 = from preset` sentinel, `warmup_steps` being counted in optimizer steps rather than epochs (with the arithmetic showing why every shipped preset's `100` is wrong on a small dataset), `dry_run`, and the fact that `exit_code 0` does not mean success because upstream catches its own exceptions and exits 0 either way.

## 6. Package contents

**`docs/` was shipping in the archive.**
`96725e5`. It was **1.2 MB of the 1.88 MB** built for 2.5.0 — the repository's own design documents, which nobody installing the pack opens. Adding the node screenshots would have pushed the archive past 9 MB. Added to `.comfyignore`; next publish drops from **683 files to 623**. (`web/docs/` is a different folder and still ships.)

**The 80 MiB LoRA was correctly kept out**, `41bc3ca` — under GitHub's 100 MiB hard limit but over the 50 MiB warning, and git keeps blobs forever, so every clone would carry it even after a later deletion. It would also have taken the registry archive from 1.9 MB to roughly 85 MB. Shipped as a release asset with its SHA-256 recorded instead.

**A release link that would have silently broken**, `680643a` — the download pointed at `/releases/latest`, which resolves to whatever release is newest, so the first release that did not contain the file would have landed people on a page without it. Repointed at the fixed asset URL under the `assets-v1` tag.

All three shipped workflow files were scanned for embedded credentials before committing, because Nova SQL Dump carries host/user/password widgets and a saved graph can capture them. `41bc3ca`, `d1985ce`.

## 7. The biggest single problem: a misread registry rule, shipped as fact

This one is not a bug in code. It is a wrong belief that had already cost the pack features, and 2.5.0 would have published it to every user.

**7.1 Six shipped files blamed the wrong thing for the missing lossy formats.**
`13a0234`. Six files explained the removal of mp3, m4a, opus and webm by saying the registry's scanner objected to the ffmpeg subprocess. The published rule is precise:

> "Runtime package installation through subprocess calls is not permitted."

That is a prohibition on **installing packages**, not on subprocess. The ffmpeg call installed nothing — argv list, never a shell string, format checked against the MIME table first, filename resolved inside the temp directory — so it never violated the standard. The likelier cause of the original 2.2.x flag is the *other* thing 2.3.0 removed: a 156 KB minified vendor bundle that nothing imported, against a rule that *does* say "Code obfuscation is prohibited in custom nodes". And 2.3.0 through 2.3.3 cleared retroactively with no further code change, which is a review lifting rather than anything in the archive.

**Four download formats were given up for nothing**, and 2.5.0 would have shipped the wrong explanation to everyone who installed the pack.

**7.2 The same misreading had been written into the pack's own standards test, where it blocked real work.**
`83c647e`. Seven failures on the merged tree, every one against a rule written locally rather than a rule the registry has. The published list is three items: no `eval`/`exec`, no runtime package installation through subprocess, no obfuscation. The local test additionally banned:

- `subprocess` outright — which refused Nova ACE LoRA Trainer running `python -m acestep…cli.train_fixed` as a child process, a permitted operation. *The same misreading that had already cost the pack its mp3 export was trying to cost it a second thing.*
- `importlib.import_module` — not in the standard at all, imported from a third-party scanner whose ruleset also reports `re.compile` as CWE-95.
- A regex containing a prohibited method name in JavaScript, and the bare words *eval* / *exec* / *subprocess* appearing in prose — so a training node could not document that it spawns a child process.

These rules were written while five versions sat flagged and nobody knew why. When the flag lifted, it lifted on versions that still contained every pattern the rules forbade — so they had been guarding against something that was never happening while blocking things that were.

The replacement encodes what the standard actually says: execution **and** installation on the same line. It passes `subprocess.Popen(argv, …)`, passes an f-string telling the user what to run, and fails `subprocess.run([sys.executable, "-m", "pip", "install", …])`. Eight cases were run through it, four that must flag and four that must not. It is stated in the file that this is a grep and not an analysis — split the call across two lines and it sees nothing.

**7.3 Having removed the wrong reason, lossy export was then dropped on its own merits.**
`1abe21b`. Two reasons, neither about the registry: the node's own SAT row reads `0.0000%` on a 320k mp3 (ffmpeg's `astats` agrees with `Flat factor: 0.000000`), so a measurement node handing you a lossy file is handing you a file its own panel cannot honestly read; and the pack now has Save Audio FLAC 24-bit and Save Audio WAV under Delivery & Metadata, which is where a delivery format belongs. The `lameenc` plan is dropped rather than deferred, and every "expected back" string is gone from README, the node's help page, `routes.py`, `defaults.py` and the download menu. `test_formats` gained "no lossy format is offered", because a deliberate absence that is not pinned is an absence somebody eventually treats as a gap.

## 8. A measurement bug fixed in the same window

`0d83437` — **the LUFS badge read 3.84 LU low.** Reported by NovaFemme after a second opinion flagged the badge against the file, then measured against ffmpeg's `ebur128` rather than against another opinion:

```
as shipped   mono downmix, no gating     -17.29 LUFS   <- the badge
channel rule fixed, no gating            -13.59 LUFS   (+3.70 LU)
gating fixed, mono downmix               -17.15 LUFS   (+0.14 LU)
both fixed = BS.1770 integrated          -13.45 LUFS   (+3.84 LU)
ffmpeg ebur128                           -13.50 LUFS
```

The suspicion was gating; gating was worth 0.14 LU. The error was almost entirely the channel rule — `mono = waveform.float().mean(dim=0)`, where BS.1770 defines loudness over the **sum** of per-channel weighted powers. Averaging L and R is a different quantity: 3 dB low for correlated stereo, up to 6 dB for uncorrelated.

A third fault, unreported: the K-weighting table is published for 48 kHz, and a digital filter's response is fixed in normalised frequency, so running it at 44.1 kHz slid the shelf from 1682 Hz to 1545 Hz and measured a curve the standard does not describe. The filter is now re-derived per rate through its analog prototype.

Verified against ffmpeg on five files at both rates: 0.00 LU on four, 0.05 on the fifth. The old implementation fails all four of the properties any correct implementation has.

## 10. The pattern, if a pattern is wanted

Three causes account for nearly all of it.

1. **Built on one machine, for one machine.** Nine days of development in a live install where every optional package was already present, so a fatal import, a non-portable import style and a hardcoded home directory all ran clean. None of them could have failed there. They were found by reading the diff, not by running it.

2. **The metadata and the code drifted apart for two minor versions.** README, `pyproject` description, help pages and category constants were all still describing a three-node pack while the code became a twenty-eight-node suite. Nothing checked them against each other.

3. **One misread sentence became institutional.** A ban on *installing packages via subprocess* was read as a ban on *subprocess*. It cost four export formats, was about to be published to users as fact, and had been hardened into the project's own test suite where it was blocking a legitimate feature. Reading the published rule verbatim resolved it.

All three are now covered by tests or by explicit checks in the release procedure.
